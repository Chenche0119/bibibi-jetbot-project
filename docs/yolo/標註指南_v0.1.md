# YOLO 標註指南 v0.1

依 `YOLO模型建置流程_草案.md` 第 3.6 節與討論紀錄 D1–D7 整理，供上 Roboflow 標註時對照。
實例截圖尚未加入（待組員從 `dataset/` 挑選後補在各節「範例」處）。

## 1. 通則

- YOLO 的任務是辨識畫面組成（有哪些類別、大致位置、數量），重點是每張影像的類別是否正確，不要求像素級框精度。
- 一張影像中每個符合條件的目標都要各畫一個框，不可漏標。
- 以原始 640×480 影像目視判斷；訓練輸入為 320×320，遠處目標可能縮到模型看不見（見草案風險 9、10）。
- 不確定時不要自行發明規則，記在下方「待決定／疑難案例」，由組內統一。

## 2. 各類別規則

| 類別 | 標註範圍 | 標註條件 |
|---|---|---|
| person（被照護者） | 腳到膝蓋線（含鞋與護腕） | 腳踝護腕（螢光粉紅＋螢光綠）可見才標 person |
| bystander（其他行人） | 同樣為腳到膝蓋線 | 其他行人；被照護者護腕不可見（被遮擋、出畫面、太遠）時，也標 bystander |
| dynamic_obstacle | 車輛或腳踏車整體外框 | 所有可見車輛（汽車、機車、公車）與腳踏車都標 |
| ground_hazard | 尚未決定 | 台階邊緣、坑洞邊界模糊；見第 4 節 D8 |

## 3. 判斷流程（針對畫面中的每個行人）

1. 看得到腳踝護腕嗎？
   - 看得到：標 person。
   - 看不到（遮擋、出畫面、太遠）：標 bystander。
2. 路面紅線與粉紅色花不是護腕，不可因顏色相近而標 person。
3. 畫面中有多個行人時，只有帶護腕者為 person，其餘都是 bystander。

## 4. 待決定／疑難案例

| 項目 | 狀況 |
|---|---|
| ground_hazard（D8） | 尚未討論：縮小定義，或改由避障模型與超音波處理 |
| 護腕可見但像素過少 | 以 `preprocessing/band_review.csv`（`scripts/review_band_visibility.py` 產出）人工覆核，統一最小像素門檻 |
| 模糊影像 | 0557、0548、0542 可考慮剔除，標註前先確認 |
| 被截斷的目標 | 框到畫面邊緣即可；是否標註極度殘缺的目標待組內決定 |

## 5. 標註完成後檢查

- test 集（`preprocessing/test_set_files.txt` 的 75 張）不做增強，標註規則需與 train／val 一致。
- 每個類別在 train、val、test 都至少有樣本，缺類別時回報而不是硬切。
- 標註規則若變動，依討論紀錄的「更換實驗設計重跑時的檢查清單」重新檢視 D1–D6。
