## 1. 已確認的設計決定

- 模型：YOLOv8n，Colab GPU 訓練，Nano 上轉 TensorRT FP16。
- 影像來源：以 JetBot 鏡頭實拍為主。
- 被照護者以組內成員或已同意者模擬，不拍攝真實孩童／長者。
- 類別：`person`（被照護者）、`bystander`（其他行人）、`ground_hazard`（石頭、台階邊緣、坑洞）、`dynamic_obstacle`（腳踏車、車輛）。
- sampling rate 解讀為「從 raw 資料抽樣的比例」（25／50／75／100%）。

## 2. 流程總覽

P1 拍攝 → P2 標註與切分 → P3 HSV 環境分析 → P4 增強版本建立 → P5 實驗訓練 → P6 評估 → P7 Nano 部署與實測 → 回到 P1 補資料

## 3. 各階段內容

### P1 拍攝規劃
- 拍攝矩陣：場景 × 光線（晴／陰／傍晚／室內）× 拍攝面向（sides）。
- 約 500 張原圖，各類別數量盡量平衡，並記錄每類的目標張數。
- 每張圖記錄 metadata：場景、日期、時段、天氣、面向（檔名或 CSV）。
- 避免連拍：同一位置至少間隔數秒或移動後再拍，降低近似重複影像。
- 鏡頭高度、解析度與實機一致。

### P2 Roboflow 標註與資料切分
- 建立 Object Detection 專案，上傳原圖，統一標註規則文件。
- 標註規則：框住可見部分、被截斷物件也標、`ground_hazard` 的框範圍（台階邊緣／坑洞）需先定義並附範例圖。
- 品質檢查：抽檢 10%，兩人交叉標註一部分以檢查一致性。
- 切分：依場景或拍攝日分組，先固定切出 test 集，test 不做增強，再切 train／val。
- 增強只套用在 train，val／test 維持原圖，避免資料洩漏。

### P3 HSV 環境分析
- 對每張圖計算 H／S／V 的平均、標準差與直方圖。
- 比較訓練集與實測環境（校門到教學大樓步道）的分布重疊：histogram intersection 或 Bhattacharyya distance，並建議附上簡單圖表。
- 用途：量化「資料夠不夠」，並作為亮度、飽和度增強範圍的依據。
- 「environment criteria」的校準工作對應此階段。

### P4 Roboflow 版本建立
- v0：raw（auto-orient、resize 至 320 或 416，兩者在 P5 擇一固定）。
- v1–v3：旋轉 ±15°、±30°、±45°（對應老師的 45° 以內）。
- v4：依 P3 結果設定的亮度／曝光／飽和度增強。
- v5：旋轉最佳值＋HSV 增強組合。
- 注意：Roboflow 旋轉會讓標註框變大，需抽查增強後影像是否合理。
- 被照護者（`person`）穿戴高飽和度色環布料作為辨識線索，因此**不做色相（hue）增強、不轉灰階**，飽和度增強範圍需限縮；訓練時 `hsv_h` 設為 0 或調低。
- 需補拍負樣本：其他行人穿著接近色環顏色的衣物。
- 匯出格式：YOLOv8。

### P5 實驗訓練（Colab）
| 因子 | 水準 |
|---|---|
| 資料版本 | raw、v1–v5 |
| 抽樣比例（sampling rate） | 25%、50%、75%、100% |
| 正則化強度 | weight_decay：0.0001、0.0005（預設）、0.005 |
| 隨機種子 | 至少 3 個 |

固定項：YOLOv8n、imgsz、epochs、patience、batch size。
正則化說明：老師的 dropout rate 解讀為「不同正則化強度對 overfitting 的影響」。YOLOv8 偵測模型沒有可用的 dropout（僅分類任務有），因此以 `weight_decay` 作為主要變因；一次只變動一個因子，確認趨勢後再視需要加入 `freeze`、`mosaic` 等作為補充。overfitting 以 train／val loss 差距與 mAP 差距判讀。
組合數量會很大（資料版本 × 抽樣比例 × 正則化 × 種子），建議分階段：先固定 100% 資料比較 raw 與各增強版本，再固定最佳增強版本比較抽樣比例與正則化。

### P6 評估
- 指標：mAP50、mAP50-95、各類別 precision／recall、confusion matrix。
- efficiency 定義（待定）：每增加一單位訓練資料或訓練時間，mAP 增加多少。
- overfitting 判讀：train／val loss 曲線、train 與 val mAP 差距。
- 用 test 集與 HSV 分群（亮／暗場景）做分層評估，找出模型弱點。

### P7 Nano 部署與實測
- 匯出 ONNX（opset 以 TensorRT 8.2 可支援為準，需實測），用 trtexec 轉 FP16。
- 與避障模型（AlexNet）併跑，量測實際 FPS，目標 ≥15 FPS。
- 戶外步道實測，記錄誤判案例並回補資料。

## 3.5 現有資料集檢視結果（task_A_alert_20261013，2026/10/13）

- 共 700 張（`alert_road` 561、`alert_bg` 139），解析度皆為 640×480。
- **損毀**：`alert_road_am_0295`～`0312` 共 18 張為 0 byte，已確認找不到原始檔、無法復原，永久排除（可用資料 682 張：road 543、bg 139）。
- **光線單一**：全為上午（am）拍攝，V 平均 118、標準差約 6，缺少傍晚、陰天、逆光。
- **色環為腳踝護腕（螢光粉紅＋螢光綠）**：多數畫面只拍到小腿以下；色環面積中位數約 1,245 px（640×480），縮至 320×320 後約 300 px，10% 分位僅約 50 px。約 5% 的 road 畫面色環不可見或過小（例如 0549、0505）。
- **bg 圖含動態物**：公車、汽車、機車、腳踏車、路人；已決定要標註 `dynamic_obstacle`／`bystander`。路面紅線與粉紅色花會造成顏色閾值誤判，故不能單靠 HSV 閾值偵測色環。
- 相鄰影像近重複僅約 7 組；畫面有輕微 roll，旋轉增強以 ±15° 為合理起點。
- 尚無標註檔與 metadata（場景、時段、距離），切分前需補。
- 較模糊的影像可考慮剔除：0557、0548、0542。

## 3.6 YOLO 角色與標註規則（2026/10 組內決定）

**YOLO 的角色**：跟隨模組已移除，距離改由超音波提供。YOLO 負責「辨識畫面組成」（有哪些類別、大致位置、數量），作為後續訊息通報時影像解讀與警報通知的依據。因此：
- 重點是每張影像「有哪些類別」是否正確，框的像素級精度不是重點。
- 評估以 per-image class presence（precision／recall）與 mAP50 為主，mAP50-95 為輔。
- 通知內容要避免被遠處小目標干擾，建議在通報層設定最小框尺寸或距離門檻，不影響標註。

**標註規則 v0.1**
| 項目 | 規則 |
|---|---|
| person（被照護者） | 框「腳到膝蓋線」（含鞋與護腕）；護腕可見才標 person |
| bystander（其他行人） | 同樣框「腳到膝蓋線」；被照護者護腕不可見（被遮擋、出畫面、太遠）時也標 bystander |
| 護腕「可見」判斷 | 以原始 640×480 目視為準（見下方風險 9） |
| dynamic_obstacle | 所有可見車輛與腳踏車都標 |
| ground_hazard | 尚未決定（見風險 2） |

## 4. 待討論／風險

1. **person 與 bystander 的區分依賴色環布料**：已確認被照護者穿戴高飽和度色環布料。風險在於布料被遮擋、光線改變色彩，或路人穿相近顏色；建議先做小規模 pilot，看 confusion matrix，並在 metadata 記錄布料是否可見。
2. **ground_hazard 的標註難度**：台階邊緣與坑洞邊界模糊，可能需要縮小定義或改由避障模型／超音波處理。
3. **Roboflow 方案**：免費版資料集為 public；價格與增強上限需以[官方定價頁](https://roboflow.com/pricing)確認。
4. **「準確率 ≥90%」的定義**：構想書未指明是 mAP50、precision 還是 accuracy，需與組員統一。
5. **sampling rate 與正則化**：紀錄單內容為與老師核對後所記，視為已確認。sampling rate 為 raw 資料抽樣比例，用來觀察資料量對 overfitting 的影響；dropout rate 的目的是比較不同正則化強度對 overfitting 的影響。因 YOLOv8 偵測模型無 dropout，實作上以 `weight_decay` 作為正則化變因（此為實作層面的替代，不改變老師的實驗目的）。
6. **各階段時程與負責人**：紀錄單中的預定完成日尚未填寫。
7. **person 標註框定義（已決定）**：框「腳到膝蓋線」，person 與 bystander 一致。跟隨模組移除後，框高度不再用來估距離，精度要求降低。
8. **補拍規劃（目前傾向不補拍）**：傍晚／陰天光線、遠距離與色環被遮擋、路人穿相近高飽和度衣物的負樣本。不補拍的代價是泛化能力只代表同一早晨、同一路線，需在報告中明寫。
9. **護腕「可見」以 640×480 目視判斷的風險**：訓練輸入為 320×320（縮小一半），遠處護腕在 640×480 看得到，模型卻可能看不到，會讓「person」標註裡混入模型無法辨識的樣本。緩解做法：用 metadata 的 `band_px`（護腕色塊像素數）找出「目視可見但像素過少」的影像覆核，或統一一個最小像素門檻。
10. **所有車輛與腳踏車都標**：遠處小目標在 320×320 下僅剩數像素，模型很難學；評估時建議設定最小框尺寸（例如邊長 <12 px 不計入 mAP），通報時也只報告足夠大或夠近的目標。
11. **YOLO 輸出如何串到通報**：需決定輸出格式（類別、數量、左／中／右位置）與 LLM／Line@ 訊息的接口（顏尚岳負責 LLM 優化）。
