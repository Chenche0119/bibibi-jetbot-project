# 標記顏色校正

`marker.py` 的 HSV 門檻要量出來，不能猜。這個資料夾就是量的流程。

**這一步等價於神經網路的「訓練」**，只是參數從 1100 萬個變成十幾個，
不用 GPU、不用標框。

> **目前狀態（2026-10-06）：已完成校正。** 58 張實拍照、0.3～2.0 m 全部偵測成功，
> 只靠桃紅或只靠綠色也都 58/58。實測數字與每個門檻的取值理由寫在 `marker.py` 的
> `MarkerConfig` 註解裡。換布條材質、換相機或換相機角度時才需要重跑。

---

## 標記規格（定案）

| 項目 | 規格 |
|---|---|
| 形式 | 布條，**包住一條腿的腳踝一圈**（正面、背面、側面都看得到） |
| 顏色 | **上桃紅、下螢光綠**（原本規劃螢光黃，實際買到的是綠） |
| 判定 | **桃紅或綠色任一成立就算找到**（`require_both = False`） |

用兩個顏色是為了**互相備援**，不是雙重確認：一個顏色在某種光線下太淡、被陰影吃掉時，
另一個還在。實測例子：`0.5m_03` 的桃紅落在褲管陰影裡只剩 705 px，綠色仍有 1881 px。

只貼一條腿，走路時會被另一條腿週期性遮住，靠 `grace_seconds`（1.5 秒）撐過去。

---

## 為什麼非做不可

同一張色紙在日光燈下、窗邊、陰影裡，HSV 讀數會差很多。沒校正就上車，最可能的兩種症狀：

| 症狀 | 原因 |
|---|---|
| 完全鎖不上，一直停在 `waiting` | 門檻太嚴，標記抓不到 |
| 沒貼標記的人也鎖得上 | 門檻太鬆，抓到的是褲子、地板或樹叢 |

兩種都不會報錯，只會「行為怪怪的」。這次校正就實際發生過第一種：
原本估計的門檻要求 S ≥ 150，實測桃紅中位數只有 153、綠色只有 95，照估計值上車會幾乎全部抓不到。

## 流程

### ① 在 JetBot 上拍照

開 `capture_samples.ipynb`，執行第一格：左邊是即時畫面，右邊是拍照按鈕。
「任務」選**色塊校正**，存成 PNG（JPEG 的色度抽樣會把色彩解析度砍半，對小色塊是災難）。

- **攝影機角度已經固定。** 角度一改，全部重來
- **解析度 640×480**，與 `live_demo_following_sm.ipynb` 一致

| 前綴 | 內容 | 張數 | 用途 |
|---|---|---|---|
| `close` | 約 0.3 m 特寫 | 5~8 | 量顏色 |
| `0.5m` `0.8m` `1.5m` `2.0m` | 站立全身 | 各 3~5 | 驗證距離 |
| `bg` | 實際場地、有路人但**沒人綁布條**，背景有樹叢更好 | 3~5 | 測誤判 |

特寫要涵蓋不同光線（室內 / 戶外 / 陰影）。距離照要包含**走路中途兩腿交錯的那一瞬間**。
多位配戴者可以在前綴後加代號，例如 `close_256_01.png`（`_256` = 第二位配戴者）。

檔名不要出現「數字＋m」以外的距離寫法，例如 `bg_2m` 會被當成 2 m 的距離照。

拍完用 `pack_samples.ipynb` 打包下載回筆電（不需要網路，點連結就能存）。

### ② 在筆電上量顏色

```bash
python analyze_marker.py samples --pick
```

只挑 `close` 開頭的特寫來框。每張圖會開兩次視窗：先框桃紅區，再框綠色區。
視窗會自動放大到塞滿螢幕，框「緊」一點，不要框到旁邊的褲子或地板。

跑完會印出兩行可以直接貼進 `marker.py` 的門檻，同時報告**過曝比例**。
超過 5% 就代表材質的鏡面高光已經把顏色打成白色 —— 換霧面材質。

公式算出來的是起點。2026-10-06 那次另外依個別照片手動放寬了桃紅的 S、V 下限，
並把綠色的 V 下限**拉高**到 150（理由見下一節），都寫在 `marker.py` 的註解裡。

### ③ 貼回 marker.py

打開 `../marker.py`，找到 `MarkerConfig`，用實測值取代。

### ④ 驗證

```bash
python analyze_marker.py samples --check --save-masks
```

校正照沒有人框，所以 `--check` 一律**搜整張畫面**（JetBot 鏡頭貼近地面，
人在畫面上半部，只搜下半部會全部判成 FAIL）。輸出：

```
有標記的照片:58 張,判定成功 58 張
  只靠桃紅單獨就成立:58 張   只靠綠色單獨就成立:58 張
  兩色都成立:58 張   只有一色成立(另一色靠不住):0 張
背景照(不該找到):5 張,誤判 0 張
成功的最遠距離:2.00 m
```

`bg_` 開頭的照片會自動當成「不該找到」來統計誤判。

`--save-masks` 會把偵測框疊在原圖上存到 `samples/check_out/`，用眼睛確認
框有沒有落在布條上，而不是落在別的東西上。**「通過」不代表框對了**，一定要看。

### ⑤ 回歸測試

```bash
python ../test_marker.py
```

這支測的是**邏輯**不是門檻（合成影像），改完門檻跑一次，確認沒把邏輯改壞。

## 綠色比較容易誤判

綠色可以單獨成立之後，戶外的**樹叢、盆栽**就成了問題：色相跟螢光綠落在同一區（H 38~48），
背景綠色塊最大有 2016 px，比 2.0 m 處的真布條（207 px）還大。

能分開兩者的是**亮度**：螢光布 V 中位數 214，樹葉 V 中位數 119、98% 在 148 以下。
綠色 V 下限拉到 150 之後，標記綠保留 91%，背景綠只剩約 2%。

| | 最小面積門檻 | 真布條最小 | 背景雜訊最大 | 安全間距 |
|---|---|---|---|---|
| 桃紅 | 80 px | 209 px | 24 px | 約 9 倍 |
| 綠色 | 150 px | 187 px | 100 px | 約 1.5 倍 |

綠色的間距窄得多，是兩色中比較容易誤判的那個。上車後只搜人框下半部，背景大多會被排除，
但樹叢剛好在腿旁邊時仍可能進到搜尋範圍 —— 列入報告的已知限制。

## 上車之後

`live_demo_following_sm.ipynb` 的畫面左上角會多顯示 `M<數字>`（這一幀的桃紅像素數），
標記位置會畫一個**洋紅色細框**。

| 看到什麼 | 意思 | 怎麼辦 |
|---|---|---|
| 洋紅框穩定跟著腳踝 | 正常 | 不用動 |
| 框一直閃爍 | 門檻太嚴 | 把 S / V 下限調低一點 |
| 框跑到褲子、地板或樹叢上 | 門檻太鬆 | 把 H 範圍縮窄、S / V 下限調高 |
| `M` 完全不出現 | 沒抓到 | 先確認解析度和光線與校正時一致 |

要量化「穩不穩定」，用 notebook 裡的**標記穩定度測試**（開始統計 → 走 30 秒 → 結束統計）：
配戴者測試看「最長連續認不出」是否小於 1.5 秒；路人測試看「認出布條的幀」是否為 0。
